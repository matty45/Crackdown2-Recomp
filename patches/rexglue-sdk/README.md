# rexglue SDK patches

Patches against rexglue SDK v0.10.0. 0001-0003 are optional on PC, 0005 only matters when running codegen 0006 is required for correct rendering on the Vulkan backend (so for Linux and Android, and Windows with `--gpu=vulkan`), 0007 and 0008 are required on PowerVR GPUs (Pixel 10) and harmless elsewhere; 0009-0011 are performance fixes for every Vulkan platform: the prebuilt SDK works without them; apply them only if you
build the SDK from source (`git clone --recursive --branch v0.10.0 https://github.com/rexglue/rexglue-sdk.git`, then
`git apply <this repo>/patches/rexglue-sdk/*.patch` inside the clone and build with its `win-amd64` / `linux-amd64`
preset). Drop the resulting `rexgpu-xenos*.dll`/`.so` **and** the matching `rexruntime*` library beside the game
executable together: the runtime and the GPU plugin from different builds are not ABI compatible.

| Patch | What it does | Measured effect (NUC, Radeon 780M, tutorial room) |
| --- | --- | --- |
| 0001 | `ExecutePacketType0` writes register ranges through `WriteRegisterRangeFromRing` (one `copy_and_swap` per shader-constant block instead of one virtual call per dword, as upstream Xenia does); caches the `RegisterFile::GetRegisterInfo` lookup; adds `gpu_invalidation_widen_kb` (CPU write-watch invalidation window, default unchanged at 256 KB) and `gpu_log_shared_memory_stats` (logs upload and invalidation rates every 5 s). | Type-0 register handling drops from 29% to 11% of the "GPU Commands" thread. The widening cvar made no measurable difference for this game; it is there for diagnosis. |

| 0002 | Keyboard/mouse driver: converts mouse movement to a right-stick deflection once per 12 ms window and gives every pad poll in that window the same value (the stock driver drains the delta on the first poll, and Crackdown 2 polls the pad several times per frame from more than one thread, so the camera mostly saw a zero stick and the mouse barely moved); mouse distance is banked and paid out as time at stick deflection above the game's deadzone. Keybinds: a bare modifier (`Shift`) can be bound as a key, and a bare key keeps firing while a modifier is held unless another bind claims that exact combination (arrows vs `Shift+arrows`). Makes `SaveConfig` write valid TOML (backslashes in Windows paths and quotes are escaped; the stock SDK's F4 **Save to config** writes `log_file = "C:\cd2\x.log"`, which its own parser then rejects, so nothing loads at the next start). Rate-limits the per-draw "Memexport done to an unresearched format" warning to once per format (Crackdown 2 memexports `k_8_8_8_8_A` every frame; the stock SDK logs ~1,300 lines/s, which rotates the log away and costs GPU-thread time). Adds `readback_memexport_async` (default off): instead of a synchronous per-draw readback, all memexport ranges of a frame are copied with one batched copy when the frame closes and the newest GPU-completed copy is written to guest memory when the next frame opens, so readback never stalls the GPU thread (results arrive 1-3 frames late). | The warning fix is pure overhead removal. The async readback runs at the same frame rate as `--readback_memexport=false` (vs 6 FPS for the stock synchronous path in the city) and renders identically; it is kept for titles that do read memexport results on the CPU. Crackdown 2 does not, so the launcher keeps readback off. |


| 0003 | Vulkan backend: a transfer pass and a draw pass into the same framebuffer are told apart by the transfer destination view, so a draw after an ownership transfer no longer reuses the transfer's render pass. Adds the debug cvars `gpu_log_textures` (log every host texture and render target creation) and `gpu_ignore_gamma_ramp` (keep the identity gamma ramp), and dumps translated SPIR-V when `dump_shaders` is set (parity with the D3D12 backend). | Diagnostic aids for the Vulkan colour-tint investigation; no measured performance effect. |

| 0004 | Android (arm64) port of the SDK: `android-arm64` CMake platform (no host tools when cross-compiling, 16 KiB page alignment, SDL3 shared, `-fexperimental-library` for `std::jthread`), AAPCS64 fiber context switch (Bionic has no `makecontext`), libc++ gaps (`std::from_chars` for floats, `clock_time_conversion`), `ANativeWindow` presenter surface with background/foreground reattachment, `SDL_main` entry through SDL's activity (`WindowedApp::GetSoleCreator`), app folder from `REX_APP_FOLDER`, GPU plugin loaded by soname, logcat sink, no robust mutexes on Bionic. Required for the Android build; a no-op on other platforms. See [docs/android.md](../../docs/android.md). | Builds and starts on a Pixel 10 Pro (PowerVR, Vulkan 1.4); game testing in progress. |

| 0005 | Codegen: honour `analysis.max_jump_table_entries` from the manifest. The value is an init-only cvar, and the manifest is read after cvars are finalised, so it has to be set under the cvar lifecycle override (0.10.0 drops it silently and stays at 512). In 0.10.0 the key belongs in the binary's table (`[entrypoint.analysis]`); a top-level `[analysis]` table from older manifests is ignored entirely. Crackdown 2 needs 519: one switch table in the animation attribute loader has 518 entries, and with the cap at 512 the generated `switch` traps on attribute ids 512-517 (`__builtin_trap`: `ud2` on x86, `brk` on arm64) when the global level loads. With the prebuilt 0.10.0 tool the build wraps codegen to set `REX_MAX_JUMP_TABLE_ENTRIES=519` instead. | Found on Android, where the trap killed the process while loading the game database (the data holds attribute ids 512-516). The Windows build was generated with the same cap and has not shown the crash; why it survives there is not established, so its generated code should be refreshed with the fix as well. |

| 0006 | SPIR-V shader translator (Vulkan backend): the per-fetch texture result exponent bias (`exp_adjust`, bits 13:18 of fetch-constant word 3) was read from word 4, where those bits belong to the LOD bias. Every texture sample through a fetch constant with a non-zero LOD bias was multiplied by 2^(garbage), so the whole scene came out dark or tinted (red/blue/green depending on which planes or channels happened to get a large negative exponent); the D3D12 (DXBC) translator reads word 3 and was never affected. Fixes the Vulkan rendering defect on Linux (Intel), Windows (AMD), Android (PowerVR) and lavapipe. | Found with RenderDoc on the title-screen Sofdec video draw: one of the three YUV plane fetch constants carries a LOD bias of -0.5, which leaves 0b111000 (-8) in bits 13:18 of word 4, so that plane was sampled at 1/256 of its value and the frame blended to black. Title screen and gameplay now match D3D12. |

| 0007 | Vulkan backend: on the PowerVR driver, write each guest texture and sampler descriptor with its own `VkWriteDescriptorSet` instead of one write whose `descriptorCount` rolls over into the following bindings. The roll-over is valid Vulkan, but that driver mishandles it and every texture binding of a draw samples the same image. Other drivers keep the single write (fewer driver calls per draw). | Found on Android: the 1080p intro movies and the city cutscene rendered as flat grey with green and magenta, because the three YUV planes of each video frame all sampled the V plane (RenderDoc replay hid it, since RenderDoc splits such writes itself). With the patch the intro movies, title and save screens render correctly on the Pixel. |

| 0008 | Vulkan render target cache: on devices without `VK_EXT_shader_stencil_export` the backend copies stencil between depth buffers with eight per-bit draws that discard pixels lacking the bit. For a depth source only the stencil view is bound, and the shader never built the value it tests, so the discard was skipped and every pixel got every bit (stencil 0xFF). The shader now tests the source stencil directly. | Found on the Pixel 10 Pro: in the city the whole frame, HUD included, turned red, because Crackdown 2 reinterprets that depth buffer as colour and the 0xFF stencil byte lands in red. Desktop GPUs have stencil export and never take this path. |

| 0009 | POSIX threading: `WaitMultiple` no longer polls. Every signal of an event, semaphore, mutant, timer or thread bumps a global generation and wakes blocked multi-waits, which re-check their handles immediately (previously a 1 ms polling loop, with two busy-spin paths: a bare yield when another waiter held a handle's mutex, and `sleep_for(0)` for the last sub-millisecond of a timed wait). The timer queue thread uses disruptorplus' `blocking_wait_strategy` instead of `spin_wait_strategy` (whose timed wait passed `condition_variable::wait_until` arguments in the wrong order - fixed). | Pixel 10 Pro in the city: two guest threads at 100% of a core each and the timer thread at ~50% were pure spinning; afterwards only the real game thread stays busy and the prime core holds ~2.9 GHz instead of 1.6-2.3 GHz. Linux title screen holds 30.0 FPS. |

| 0010 | Vulkan: each dynamic rendering pass's render area is shrunk at pass end to the union of the scissors of its draws and its clear rectangles (only when every attachment is loaded, not cleared). The render target cache always passed the whole EDRAM-sized attachment, so tile-based GPUs loaded and stored e.g. 1280x2048 for a pass drawing 1280x720. `--vulkan_shrink_render_area=false` turns it off. | Crackdown 2 city frame: 178 passes, 334 -> 160 megapixels loaded/stored per frame. Intro, title and city render the same on Linux (Intel) and the Pixel. No measurable frame rate change on the Pixel yet (GPU still at its top clock in game draws). |

| 0011 | Vulkan: the driver's compiled pipelines are kept in a `VkPipelineCache` persisted to `<cache_root>/shaders/local/<title>.vkpipelinecache` (loaded at start-up, saved at most once a minute while new pipelines appear and at shutdown; `--vulkan_persistent_pipeline_cache=false` disables it). The driver validates the data and ignores it after a GPU or driver change. | Pixel: 664 pipelines / 13.4 MB saved and reloaded on the next launch. Did not shorten Crackdown 2's first loading screen there (that time is not pipeline compilation), but removes driver recompiles on later launches. |

The big win needs no patch: pass `--clear_memory_page_state=false` (see the README's Performance section).
